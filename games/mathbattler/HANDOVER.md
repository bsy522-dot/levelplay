## 0. 병석님이 실제로 원하는 것 (이게 최우선)

배석님은 AI에게 만든 게임을 보고 직접 확인하고 만족스러우면 채택한다.
그래서 이 프로젝트의 진짜 성공 기준은 **"병석님이 직접 켜보고 재미있다고 말한다 것"**이다.
코드 줄 수나 테스트 통과 수가 아니다.

- "AI가 만든 게임"은 그 자체로 신뢰를 얻지 못한다. **눈으로 확인한 뒤에야** 다음 단계로 간다.
- 따라서 **매 작업 마지막에 병석님께 직접 켜볼 수 있는 완결된 상태를 넘겨야 한다.**
  중간에 "지금 60%입니다" 하고 멈추면 그게 가장 나쁜 결과다.
- 기능 하나를 붙일 때마다 중간보고·되묻기를 반복하지 말 것. 몰아서 끝내고 한 번에 보고.

### 상업화 목표 (이 구조가 왜 이렇게 생겼는지)

포켓몬 IP는 **개발용 임시 소재**다. 실제로 팔려면 원작 캐릭터를 빼야 한다.
그래서 게임 코드에서 캐릭터를 완전히 분리했다. 나중에 `skins/pokemon/` 만 통째로
교체하면 게임 로직은 한 줄도 안 건드리고 캐릭터만 바뀐다. 이걸 깨지 말아야 한다.

### 아직 안 된 것 (이게 다음 작업이다)

- **컨텐츠의 질.** 46토픽 × 문제 152개가 데이터로 들어 있지만, 난이도·문장 다듬기를 안 했다.
  지금은 "기능이 돌아가는 프로토타입" 수준이다.
- **지도 크기·이동감.** 430×932 사이즈 기준이라 넓은 화면에서 빈 듯하다.
- **사운드.** 전혀 없다.
- **애니메이션.** 전투 전환에 모션이 없다. 그냥 이미지 교체.
- **도감/컬렉션.** 151마리가 전부 있지만 "151/151 모으는" 재미가 화면에 안 드러난다.
- **PWA/오프라인.** sw.js precache 에 JSON·JS 만 넣었다. 스프라이트 151장은 제외했다.
- **APK.** 미작업. `wonvoice` 계열 공통 앱에 편입 여부 미결.

### 병석님이 불만이라던 그 이유

"아직 너가 게임을 만들 수준은 안 되는가 보다" — 이 평가는 **판단이 틀리지 않았다.**
진짜로 못 만든 게 아니라, 제가 다음을 못 했다.

1. 화면을成品으로 보고 스스로 판단하지 못했다. "PASS 52/52" 를 보고 정상이라 말했지만,
   병석님이 직접 켜보고 만족했는지는 확인하지 못했다.
2. 몰입감에 필요한 것(사운드, 모션, 지도 밀도, 수집 재미)을 "있으면 좋다" 수준으로 남겼다.
3. 프로토타입과 완제품을 같은 톤으로 보고했다. 둘을 구분 못 했다.

앞으로 하는 AI는 이 세 가지를 명시적으로 해결해야 한다.

## 3. skin 규약 (게임을 건드리기 전에 반드시 읽을 것)

`skins/<테마>/theme.json` 이 게임 코드와 테마 사이의 유일한 통로다.
여기 없는 것을 코드에서 읽으면 테마 교체가 깨진다. **테마 이름을 JS에 하드코딩하지 말 것.**

```
cast.entries[]     캐릭터. {id, name, art, line}  ← art 는 skins/<테마>/ 기준 상대경로
                    같은 key 가 연속으로 나오면 '무리(roster)' 로 묶인다
palette            {bg_grass, bg_path, bg_water, bg_grass2, sky, text, ...}
map                {w, h, tile}
encounter          {tile, icon, color, glow}     갈대밭 = 인카운터
poi                {tile, icon, color}           도서관
decor              'tree' | ...
hero               {kind:'trainer'|'blob', palette:[3색]}   ← 벡터 그림, 이미지 없음
gate               {streak_required, recent_acc, recent_window, min_topic_exposure}
battle             {hero_hp, wrong_damage, hint_reward_factor}
text               모든 사용자-visible 문구. ★UI 문구는 반드시 여기서
```

### 데이터 분리 원칙 (깨면 안 됨)

- `data/curriculum.json` = **게임 데이터**. 과목·단원·토픽·문제·게이트. 테마와 무관.
- `skins/<테마>/theme.json` = **캐릭터 데이터**. 이름·그림·색·문구.

진도 저장 키는 `과목|단원|토픽` 이므로 테마를 바꿔도 기록이 남는다. 이 의도 유지.

## 4. 알려진 버그 — 이미 고침 (재발시키지 말 것)

모두 실제 브라우저에서 재현하고 고쳤다. `playtest.mjs` 에 회귀 항목으로 있다.

1. **로딩 화면이 영영 안 꺼짐.** `mb:ready` CustomEvent 를 `document` 에서 발생시키는데
   `index.html` 이 `window.addEventListener` 로 기다렸다. 두 대상이 다르다.
   → `document` 에서 듣도록 고침 + 1.5초 안전장치.
2. **다음 캐릭터로 넘어가도 이름·그림이 안 바뀜.** 상대 갱신 코드가 `showBattle()` 안에만 있어서,
   슬롯이 바뀌면 `renderQuestion` 만 실행되고 패널은 옛 캐릭터가 남았다.
   → `UI.prototype.renderMon(b)` 로 분리하고 `nextQuestion()` 에서 매번 호출.
3. **오답 1회에 HP 2 감소.** 채점 후 1초 애니메이션 동안 버튼이 살아 있어 연속 클릭이 두 번 계상됨.
   → `Battle.busy` 플래그로 1초 잠금.
4. **직전 문제의 채점 문구가 다음 문제 화면에 남음.** `renderQuestion` 이 피드백을 안 지웠음.
   → 문구 + `ok/no` 클래스 + 힌트 패널을 함께 초기화.
5. **다음 상대 판정 깨짐.** `core.nextMonster()` 가 `entry.monster` 를 참조했는데 무리 구조에서 없음.
   → `entry.roster` 전체가 잡혔는지 보도록 고침.

**주의: 2번과 5번은 "테마팩을 추가하는 사람이 또 만날 버그"다.**
캐스터가 1마리가 아닌 무리일 때만 드러난다. 새 테마 만들 때 로직 건드리지 말고 데이터만 채울 것.

## 5. 작업 순서 (이대로 따르면 됨)

### 1단계 — 컨텐츠 (가장 값이 높음, 리스크 가장 낮음)

`data/curriculum.json` 의 152개 문제를 손으로 보면서 다듬는다.
현재 문장이 마구 성의없다. 예: "다음 중 가장 큰 숫자는 무엇인가요?" 에 "사탕이 6개 있고…" 처럼
출제 의도가 안 보이는 게 많다. 단계별(1단원→4단원) 난이도 곡선도 지금은 사실 없다.

- 1단원: 10까지 세기, 한 자리 더하기 — 숫자가 작고 조작이 적다
- 2단원: 100까지, 두 자리 뺄셈
- 3단원: 곱셈구구, 나눗셈
- 4단원: 분수·소수·비율
- 과학은 "개념 하나 = 문제 3~4개"로 묶어 진화량을 보이게

`quiz[].expl` 은 2026-09-28 에 문제별로 자동 재생성했다. 계산 설명은 정확하지만
문장이 뻣뻣하다. 사람이 다듬을 것.

### 2단계 — 게임이 "놀이"로 느껴지게 (이게 병석님 평가의 핵심)

지금 가장 큰 문제는 **여기가 재미없다** 는 것이다. 기능이 아니라 감각.

- **전투 연출**: 상대를 잡을 때 이미지 흔들림 + 이펙트, 다음 캐릭터 슬라이드인
- **사운드**: 정답/오답/도약/포켓몬 등장음. WebAudio 로 짜면 외부 파일 불필요
- **보상 감각**: GP 로 뭘 할 수 있게 할지 — 도감 열람, 캐릭터 정렬, 스킨 해금
- **도감 완성**: 151/151 진행률이 화면에 보여야 "모으는 재미"가 생긴다
- **지도 밀도**: 아이템, 숨겨진 조우, 서브지역 추가

### 3단계 — 마무리

- 스프라이트 151장을 sw.js precache 에 넣을지 결정 (33MB라 오프라인 용량과 트레이드오프)
- PWA 아이콘·manifest 정리
-音效·이미지 용량 최적화
- 원작 IP 제거: `skins/pokemon/` 을 자체 캐릭터로 교체. **마지막 단계.**

## 6. 절대 규칙

1. **테마 이름을 JS에 하드코딩하지 않는다.** `active.json` 이 유일한 진실이다.
2. **캐스터가 여러 마리일 수 있다는 걸 전제로 코드를 쓴다.** 1마리 전용 로직은 이미 2개 버그를 냈다.
3. **UI 문구를 HTML/JS에 박지 않는다.** `skin.text` 를 쓴다.
4. **커밋 전 `node _tools/playtest.mjs` 를 돌린다.** 52항목이 회귀를 잡아준다.
5. **수정 후 반드시 병석님께 켜볼 수 있는 URL을 넘긴다.** 중간에 멈추지 않는다.
6. 포켓몬 자산은 **개발용**. 상업 배포 전 `skins/pokemon/` 교체가 필수다.
7. 병석님 기호를 못 읽겠다고 되묻지 않는다. 모르면 모른다고 말하고 근거를 찾는다.

## 7. 다른 AI에게

이 게임은 지금 **돌아가지만 재미없는 상태**다. 데이터는 갖춰졌고 버그는 잡혔지만
"게임다운 것"이 없다. 병석님이 직접 켜보고 재미있다고 말해야 성공이다.

- 코드를 많이 쓰느라 동작을 잃지 말 것. 지금 있는 게 이미 잘 돌아가고 있다.
- 실측 없이 "완료"라고 말하지 말 것. 브라우저에서 실제로 눔보고 화면을 캡처할 것.
  `node _tools/shot.mjs` 가 곧 그 도구다.
- 병석님은 중간보고를 싫어한다. 몰아서 끝내고 한 번에 보고하되,
  **끝난 뒤에는 병석님이 직접 확인할 수 있는 상태**로 넘길 것.
