## 0. 읽는 사람

- **덧셈·뺄셈·곱셈·나눗셈만 아는 사람.** 다른 지식은 하나도 없다고 가정한다. 주제가 미적분·양자역학이어도 같다.
  어려운 주제일수록 더 잘게 쪼개고, 더 많이 그림으로 보여 준다.
- 화면은 **폰**이다. 한 장에 글은 짧게, 그림은 크게.
- 말투는 지금처럼 오박사의 다정한 반말(~야, ~해, ~란다). 꾸짖지 않는다.

## 1. 낱말·기호 규칙 (가장 중요)

1. **처음 나오는 어려운 말은 그 자리에서 풀어 쓴다.** 예: "기울기(옆으로 1칸 갈 때 위로 몇 칸 올라가는지)".
2. **기호도 낱말이다.** x, i, θ, π, √, log, ∫, f'(x), Σ, %, ° … 처음 나올 때 말로 뜻을 붙인다.
3. 한자말 대신 쉬운 말: 이항 → "반대쪽으로 옮기기", 계수 → "x 앞에 붙은 수", 진수 → "로그 안에 든 수". 공식 이름은 써도 되지만 뜻을 같이 쓴다.
4. 한 문장 = 한 생각, 40자 안팎. 숫자는 작고 구체적으로(3, 5, 10…).
5. 영어 원어는 꼭 필요할 때만 괄호로 한 번.

## 2. 강의 (`lectures.json` 한 주제)

```json
{
  "title": "아이 눈높이 제목",
  "why": "1~2문장: 옛날 사람들이 무엇 때문에 곤란해서 이것을 만들었고, 덕분에 무엇이 편해졌는지",
  "slides": [ { "kind": "story", "h": "🤔 …", "text": "…", "viz": {…}, "steps": ["…"], "tip": "…" } ],
  "key": "한 줄 핵심",
  "verified": true
}
```

장 순서 (8~11장):

| 차례 | kind | 제목 예 | 내용 |
|---|---|---|---|
| 1 | `story` | 🤔 옛날 사람들의 골칫거리 | **실제 역사**: 누가·언제·무슨 일 때문에 곤란했나. 확실한 사실만. 모르면 인물·연도 없이 생활 속 곤란함으로 |
| 2 | `idea` | 💡 그래서 생각해 낸 방법 | 발명·발견을 한 문장 + 비유 |
| 3 | (없음) | 🧸 비유로 보기 / 🎁 이런 문제 | 진짜 물건·상황 그림(`scene`, `icons`) |
| 4~5 | (없음) | 👀 그림으로 보기 | **그래프로 그릴 수 있으면 반드시 `plot`** (함수·좌표·변하는 양). 회전이면 `turn`, 같게 맞추기면 `balance` … |
| 6~7 | (없음) | ✏️ 한 단계씩 | 예제 하나를 `steps`로. **한 단계 = 계산 하나**, 사칙연산만 |
| 8 | `oops` | ⚠️ 많이 하는 실수 | `vs` 그림(헷갈린 생각 vs 맞는 생각). 문제의 틀린 보기와 연결 |
| 9 | `now` | 🌍 지금 어디에 쓰일까 | 생활 예 2~3개 (+ `timeline` 가능) |

- 한 장의 `text`는 **120자 이하**, `steps`는 5개 이하(각 35자 이하), `tip`은 50자 이하.
- **그림(viz)이 있는 장이 5장 이상.** 그림이 없는 장은 3장 이하.
- 마지막 '한 줄 핵심' 장·만화·영상·'아까 그 문제의 정답' 장은 프로그램이 자동으로 붙인다(쓰지 않는다).

## 3. 문제 (문제은행 한 문제)

```json
{ "id": "s_number_05", "topic": "s_number",
  "q": "문제", "help": "📖 낱말 풀이(선택)", "pic": {그림(선택)},
  "a": ["보기1", "보기2", "보기3", "보기4"], "c": 2,
  "why": "정답 이유", "steps": ["풀이 순서(선택)"], "wrong": {"0": "…", "1": "…", "3": "…"},
  "viz": {풀이 그림(선택)}, "need": "생활에서 왜 필요한지(선택)" }
```

- **q**: 문제만 읽고 "무엇을 고르면 되는지" 알 수 있게. 상황 + 묻는 것을 분명히. 70자 이하 권장.
- **help**: q 안에 처음 보는 낱말·기호가 있으면 **반드시** 넣는다(60자 이하). 예: "i = 화살표를 직각(90도)만큼 돌리는 특별한 수". 단, 정답을 알려 주면 안 된다.
- **pic**: 문제를 그림으로 보여 줄 수 있으면 넣는다(그래프·도형·수직선·물건 세기). **정답이 그림에 보이면 안 된다.**
- **a**: 보기는 짧게(20자 이하), 서로 확실히 다르게, **정답이 혼자 가장 길지 않게.**
  **정답 번호 `c`와 각 보기의 '뜻'은 그대로 둔다** — 말만 쉽게 다듬는다. 틀린 보기는 실제 오개념 그대로.
- **why**: 처음부터 차근차근 2~3문장(130자 이하). 계산은 사칙연산만, 숫자로 보여 준다.
- **steps**: 계산·추론이 있으면 2~5단계.
- **wrong**: 틀린 보기마다 "왜 그렇게 생각했을지 → 어디가 다른지 → 맞는 방법"(90자 이하).
- **viz**: 풀이를 그림으로 보여 주면 이해가 빠를 때(정답을 보여 줘도 된다 — 틀린 뒤에 나온다).
- 수학 생성기(`math*.js`)도 같은 기준: 문제 글(q), `help`, 풀이(why), `steps`, 보기별 설명, 그림.

## 4. 그림 종류 (`viz`·`pic`) — `js/learn/viz.js`

폭 360 기준으로 크게 그려지고, 움직이는 그림은 처음에 한 번 움직인 뒤 "▶ 다시 보기"가 생긴다.
`node _tools/eli5check.mjs` 가 모든 그림 글을 검사한다. 견본 그림은 `node --import ./_tools/_localfs.mjs _tools/vizgallery.mjs`.

| type | 쓰는 곳 | 모양 |
|---|---|---|
| `plot` | 함수·좌표·기울기·복소평면·적분 넓이·삼각함수 | `{"type":"plot","x":[-1,5],"y":[-1,9],"fns":[{"f":"2x+1","label":"y = 2x + 1"}],"pts":[{"x":1,"y":3,"label":"(1, 3)"}],"vecs":[{"x":3,"y":2,"label":"3 + 2i"}],"segs":[{"x1":1,"y1":3,"x2":3,"y2":3,"dash":true,"label":"옆으로 2"}],"shade":{"f":"2x","a":3,"b":4,"label":"넓이"},"circle":1,"xl":"가로 이름","yl":"세로 이름","step":1}` — 식에는 숫자, x, + - * / ^ ( ), sin cos tan sqrt abs ln log exp pi 만. (`2x`처럼 곱하기 생략 가능). 눈금은 정수 위주로 자동, `step`으로 정할 수 있음. 아래 x축 위 선분 이름표는 `"ly":-12`로 축 숫자와 겹치지 않게 |
| `turn` | 회전·각도·i 곱하기 | `{"type":"turn","stops":["→ 1","↑ i","← −1","↓ −i"],"step":90,"times":4,"cnt":"i를 곱한 횟수"}` (`times:0` = 출발 화살표만, `cnt:""` = 횟수 글 숨김) |

## 5. 사실 확인

- 역사(연도·인물·책 이름)는 **확실한 것만**. 조금이라도 불확실하면 연도 대신 "옛날에", 인물 대신 "사람들은".
- 계산은 두 번 확인한다. 정답 번호와 정답 내용이 맞는지 마지막에 다시 본다.
- 쓴 사람과 **다른 검증자**가 사실·정답·쉬움을 확인한 뒤에만 게임에 넣는다 (HANDOVER 7번 규칙).

## 5-1. 2차 점검 규칙 (2026-10-24, 독립 비판 검토·검산에서 나온 것)

1. **📖 낱말 풀이가 정답을 짚으면 안 된다.** 정답 보기에만 있는 낱말을 풀면 오답 보기의 낱말도 같이 풀거나, 그 낱말을 문제 글에 넣는다. (`eli5check` 의 '정답 흘림 의심')
2. **답을 고르는 데 꼭 필요한 낱말부터 푼다.** 문제 글과 보기 4개를 한 낱말씩 짚어, 사칙연산만 아는 아이가 모를 말(부피·자기장·전류·기울기·공정무역·판소리·추·√ …)은 전부 풀이. 우선순위: 답을 고르는 데 필요한 말 > 상황 말.
3. **규칙은 이유부터.** "부호가 같으면 +", "뒤집어 곱해", "a² + b² = c²", "적분은 F(b) − F(a)" 같은 규칙을 쓰기 전에 사칙연산 이야기(빚·묶음·동전·가위·시소·막대 쪼개기)로 왜 그런지 한 번 보여 준다.
4. **그림은 실제 모양 그대로.** `balance` 는 '양쪽이 같은 식'에만. 시소·지레는 `lever`. 도형 문제는 도형(`plot` segs), 적분은 막대 쪼개기(`plot` 의 `rects: {"f":"2x","a":0,"b":3,"n":6}`), 똑같이 나누기는 그림으로.
5. **소리가 같은 낱말은 뜻을 붙인다.** 염소(소독약 냄새 기체, 동물 아님), 수입(다른 나라에서 들여오기 / 번 돈), 산·염기·전도·부호 …
6. **에너지 ≠ 힘.** 힘은 밀고 당기는 것에만. 에너지는 '데우고 움직이고 빛나게 하는 바탕' 또는 '세기·점수'. 무게 ≠ 질량, 온도 ≠ 열도 같은 식으로 지킨다.
7. **풀이 한 줄 = 계산 하나.** '모으기', '바꾸기(100 = 10 × 10)', '이야기 → 식' 같은 연결 단계도 한 줄로.
8. **이름 외우기 문제도 쓸모를 붙인다.** '무슨 골칫거리를 풀었나'를 문제 글이나 need 에. 사람 이름은 help 에 '언제·어디·무엇을 한 사람'.
9. **틀린 보기는 실제 착각.** 웃기려고 넣은 보기는 4개 중 1개까지 (정답만 과학처럼 들리면 생각 없이 맞힌다).
10. **강의**: tip 은 그 장을 돕는 말만(새 기호·새 계산 금지), 표는 5줄 이하, 1장에서 던진 골칫거리는 강의 안에서 꼭 답을 보여 준다. 무서운 이야기는 뺀다.
11. **전해 오는 이야기는 '~했대/~라고 전해져'.** 정확한 숫자(피부 온도·물의 양·사슬 길이 …)는 출처 수준으로 맞추고, 대략이면 '약'.
12. 수학 자동 문제는 `gen: (st) =>` 로 받아 st 일 때 포켓몬 상황 문장을 만든다.
13. **문제 풀이는 같은 주제 강의의 '왜' 장을 다시 쓴다** — 강의가 피타고라스 타일·미분 띠·전개 넓이 그림으로 이유를 보여 줬다면, 그 주제 문제의 why·steps·viz 도 같은 그림·이유로 (규칙만 말하지 않는다).
14. **고학년 과학은 답을 고르는 핵심 낱말(원자·전자·분자·사슬·세포 …)을 꼭 푼다.** help 60자가 모자라면 문제 글에 괄호로 넣거나 보기 자체가 설명이 되게.
15. **help 가 새는 세 가지 꼴**: 시험하는 낱말 자체를 정의 / 틀린 보기 낱말만 다 풀어 정답만 남김 / 정답 보기만 문제 낱말을 되풀이.
16. **모양이 있는 문제는 이모지 말고 도형 그림**(plot segs·frac·area·fraccmp …). 사람·용어(간디·의무론·명나라 …)는 처음 나올 때 한 줄 소개. 수학 자동 문제의 why 에는 그 문제의 실제 숫자가 들어간다.

## 6. 금지

- "모르겠어요" 같은 보기. 정답을 `help`·`pic`·문제 글에 흘리기.
- 설명 없는 전문용어·기호. 한 장에 글만 가득.
- 무섭거나 아이에게 맞지 않는 내용.
